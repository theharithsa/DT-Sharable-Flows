Act 3 · before the agent can answer anything

Dynatrace needs to know everything first

The three layers to instrument
  • Infrastructure — OneAgent on every host, container, and K8s node; Smartscape topology auto-discovered. The agent's service map.
  • Application — Distributed tracing (PurePath), service metrics, exception capture, real user monitoring. What is failing and where.
  • Business & security — BizEvents (logins, orders, payments); Application Security (runtime vulnerabilities). Answers "how many customers" and "are we exposed."
The MCP layer on top
  • Dynatrace MCP server: npx @dynatrace-oss/dynatrace-mcp-server — or Remote MCP + dtctl for teams
  • VS Code + GitHub Copilot (or any MCP-compatible AI client)
  • OAuth token: read problems, logs, metrics, vulnerabilities, entities, bizevents — write only for notebook / Slack
  • Grail cost guard: set DT_GRAIL_QUERY_BUDGET_GB to limit log-scan spend

The MCP server is only as powerful as the data behind it.

Act 3 · take it home

Getting started safely

  • Use the Remote MCP server + dtctl for team-scale, governed access
  • Scope OAuth tokens to least privilege — read for triage, write only where needed
  • Set a Grail query budget (DT_GRAIL_QUERY_BUDGET_GB) — queries scan by GB
  • Start in one namespace with a rule file; expand once the team trusts it
